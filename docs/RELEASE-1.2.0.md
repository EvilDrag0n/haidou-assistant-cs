# 海斗助手 C# 版 1.2.0（2026-10-30）

本轮依据第二轮上机反馈修正。工作区未提供本轮诊断 JSON，因此以下为已确认的代码缺陷和本地回归结果，真实客户端效果待上机验证。

- 自动接受：引擎持有全部轮询定时器，避免局部 Timer 在方法返回后被垃圾回收。直接以 ready-check 的 state/playerResponse 判断；大厅队列读取 gameConfig.queueId，优先于上一局缓存。延迟期间复查状态，关闭开关、手动接受、换连接或匹配取消后均撤销计划；失败冷却 5 秒。
- Tab 浮层：按键设置引擎的可见状态，装备变化时持续更新；首次补取改为后台执行。兼容玩家列表数组和 players 包装，按 activeplayername 确认红蓝方；缺失价格显示 --，不再当作 0。接口错误写入诊断，保留旧值时也标明失败。数值口径仍是双方装备价值，不包含未花的金币。
- 推荐出装：依维护手册中“再次上机无效就下掉”的约定，移除写入代码、面板与托盘开关以及调试页强制写入。保留清理旧的 !!!hxdou-*.json，其他文件不动。
- 战绩聊天：每位队友单独一条，格式为 `哈哈哈#123 中等马 kda 3.1 最近胜率 46%`。四位队友通常发送四条，间隔 350ms；同批后续消息复用成功通道，记录逐条结果和已发送数量。旧 chatPrefix/chatIncludeSelf 不再影响新格式；无数据用 --。
- 构建：修复 build.bat 条件分支中的无条件退出；test.bat 等待自检退出、显示输出并传播失败退出码。

验证：test.bat 的 15 项自检通过，包括强制 GC、重新匹配、延迟取消、失败冷却、并发防重复、装备买卖刷新、红方视角、聊天格式/四条发送/部分失败/通道回退，以及旧配置不会恢复出装写入。界面脚本通过语法和元素引用检查。

如自动接受仍失败：在待接受时导出诊断，查看 status.autoAccept。若装备购买后依然全为 0：在游戏内导出诊断，新版本会附带 livePlayers（含 items[].price）和 liveError。
